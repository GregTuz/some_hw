# Итоговое домашнее задание по дисциплине "Python для инженерии данных"

Проект представляет собой комбинацию из 11 контейнеров:
- ** Контейнер с базой Postgres
- ** Контейнер с базой MySql
- ** Контейнер со скриптом, генерирущим данные для первой базы
- ** Контейнер с Zookeeper
- ** Контейнер с Kafka (по сути составной состоит из 2)
- ** Контейнер с Airflow (по сути составной состоит из 3)
- ** Контейнер со Spark

С оркестрацией контйнеров у меня не очень получилось, поэтому если какая-то фича не работает и в логах ошибка при кодключении к какой-то связной системе стоит его просто перезапустить и проблема скорее всего решится.

### Просмотр UI-ек сервисов

Почти у всех компонентов есть удобная UI-ка к которым есть доступ по соответствующим адресам:

### Airflow Web UI
- **URL**: `http://localhost:8080`
- **Логин**: `admin`
- **Пароль**: `admin`

### Spark Master
- **URL**: `http://localhost:8081`

### Kafka
- **Bootstrap Servers**: `localhost:9092`
- **Топик**: `events`

### PgAdmin
- **URL**: `http://localhost:6060`
- **host**: `postgresql`
- **port**: 5034
- **Логин**: `user`
- **Пароль**: `password`

Генерация данных осушествляется засчет контейнера fill_postgres. При подъеме docker-compose 99% вероятность, что его придется перезапускать поточу что я не настроил healthcheck.

В целом по функциональности проект сильно ограничен так как у меня не завелся Airflow и пришлось использовать готовое решение. Пусть оно не очень работает, зато сервисы успешно раскатываются и видят друг друга и при возиожности довести код до ума проект был бы отличным...
